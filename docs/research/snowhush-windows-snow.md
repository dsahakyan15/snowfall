## 2. Overlay, composition, DPI and stacking

The normal overlay is `WS_POPUP`, with exactly `WS_EX_NOREDIRECTIONBITMAP | WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`. It calls `SetLayeredWindowAttributes(...,255,LWA_ALPHA)`, shows with `SW_SHOWNOACTIVATE`, returns `HTTRANSPARENT` for `WM_NCHITTEST` and `MA_NOACTIVATE` for `WM_MOUSEACTIVATE`. The layered+transparent combination passes mouse events through; generic WS_EX_TRANSPARENT painting-order documentation alone is insufficient to explain this behavior. Toolwindow avoids the taskbar/Alt+Tab, and noactivate avoids foreground activation. (`windows/src/screen.rs:743@HEAD`, `:824`; [extended styles](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles), [layered-window hit testing](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features), [SetLayeredWindowAttributes](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setlayeredwindowattributes).)

An additional `NonRudeHWND` property is set to handle 1: the source says a full-display overlay otherwise looks like a fullscreen app to Explorer, silencing notifications and misclassifying maximized windows. This property is an **undocumented shell technique**, not a supported API contract established by Microsoft Learn. (`windows/src/screen.rs:764@HEAD`.)

D3D11 device creation requests hardware, BGRA support, feature levels 11.0/10.1/10.0. Each surface has a two-buffer BGRA8 UNORM swap chain, one sample, stretch scaling, flip-sequential swap effect and **premultiplied alpha**. DirectComposition creates a target for the HWND with topmost=true, sets a visual's content to the swap chain, applies a scale transform and effect group, sets root and commits. This topmost target argument concerns composition relative to child HWNDs, separate from top-level HWND z-order. (`windows/src/render.rs:173@HEAD`, `:414`; [D3D11CreateDevice](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-d3d11createdevice), [DCompositionCreateDevice](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-dcompositioncreatedevice), [CreateSwapChainForComposition](https://learn.microsoft.com/en-us/windows/desktop/api/dxgi1_2/nf-dxgi1_2-idxgifactory2-createswapchainforcomposition), [CreateTargetForHwnd](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositiondevice-createtargetforhwnd).)

There is one overlay per display, enumerated with EnumDisplayMonitors/GetMonitorInfoW; monitor identity is the device name, bounds/work area are physical pixels, effective DPI comes from GetDpiForMonitor, refresh from EnumDisplaySettingsW. Simulation/render sizes use `ceil(physical_size/(max(dpi,96)/96))`; the composition transform scales back to physical size. `local(x,y)` subtracts monitor origin and flips Y to bottom-up. DPI/display/work-area messages mark a rebuild; bursts debounce for 0.4 seconds and a once-per-second inventory catches missed changes. (`windows/src/screen.rs:70@HEAD`, `:289`, `:575`, `:587`, `:828`; `windows/src/snow.rs:255@HEAD`, `:275`; [EnumDisplayMonitors](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumdisplaymonitors), [GetMonitorInfoW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmonitorinfow), [GetDpiForMonitor](https://learn.microsoft.com/en-us/windows/win32/api/shellscalingapi/nf-shellscalingapi-getdpiformonitor).)

The manifest and process entry both request PerMonitorV2. **Inference/pitfall:** Microsoft cautions that GetDpiForMonitor is not DPI-aware and should not be used from a per-monitor-aware thread; preserve the observed approach only after testing mixed DPI, and consider a documented GetDpiForWindow-based design for a new implementation. (`windows/build.rs:125@HEAD`; `windows/src/main.rs:33@HEAD`; [SetProcessDpiAwarenessContext](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setprocessdpiawarenesscontext), [GetDpiForMonitor remarks](https://learn.microsoft.com/en-us/windows/win32/api/shellscalingapi/nf-shellscalingapi-getdpiformonitor).)

Normal stacking periodically puts snow above ordinary/topmost windows, but under the lowest contiguous topmost menu/tooltip/shell popup. Transparent foreign overlays are skipped while looking for that popup. Behind Taskbar instead stacks below the monitor's taskbar only while that taskbar remains topmost; a fullscreen app can remove it from that band. (`windows/src/screen.rs:526@HEAD`, `:644`; [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos).)

Behind Windows creates a **child**, `WS_CHILD | WS_VISIBLE | WS_DISABLED`, with `WS_EX_NOREDIRECTIONBITMAP | WS_EX_LAYERED | WS_EX_NOACTIVATE`; it is parented inside Explorer's wallpaper layer below icons and above live wallpapers. The disabled child needs no transparent hit-test style. Host discovery sends undocumented Progman message `0x052C`, tries the Progman children layout described in source as Windows 11 24H2+, then the older WorkerW layout. A missing host falls back to the normal overlay; Explorer restart destroys children, detected/rebuilt by the loop. Restacking is conditional to avoid multi-monitor flicker. (`windows/src/screen.rs:772@HEAD`, `:688`; `windows/src/desktop.rs:18@HEAD`; `windows/src/snow.rs:290@HEAD`, `:303`.)

Capture policy is `SetWindowDisplayAffinity(hwnd, shown ? WDA_NONE : WDA_EXCLUDEFROMCAPTURE)`; its result is discarded. Microsoft requires an owned top-level HWND and DWM composition; exclusion begins with Windows 10 2004, earlier systems behave as WDA_MONITOR, and this is not a security guarantee. Behind Windows children therefore cannot meet the hidden-from-screenshots requirement. (`windows/src/screen.rs:772@HEAD`, `:818`; [SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity).)

## 3. Window tracking and surfaces

`Tracker::list` enumerates top-level HWNDs with EnumWindows; HEAD supplements missing shell CoreWindow handles noticed by events. `describe` excludes invisible, iconic/minimized, own-process and DWM-cloaked windows; click-through overlays; selected shell classes; and effectively nonrectangular widgets. Layered-window attributes must be readable, have no color key, and have alpha at least 77/255; per-pixel-alpha widgets are skipped when querying attributes fails. This deliberately avoids treating a Rainmeter skin's mostly empty bounding rectangle as a snow ledge. (`windows/src/tracker.rs:431@HEAD`, `:452`, `:637`; [EnumWindows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows), [GetLayeredWindowAttributes](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlayeredwindowattributes).)

Frames prefer DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS), falling back to GetWindowRect; cloaking uses DWMWA_CLOAKED. Corner preference is queried for Windows 11, with maximized windows unrounded. Microsoft distinguishes GetWindowRect's potentially invisible resize borders/DPI virtualization from DWM frame bounds, which are not DPI-adjusted. HEAD additionally trims the clear shadow margin of Windows App SDK Explorer popup bridges using a heuristic. (`windows/src/tracker.rs:710@HEAD`, `:720`, `:740`, `:751`, `:506`; [DwmGetWindowAttribute](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmgetwindowattribute), [DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute), [GetWindowRect](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect).)

Surfaces are built in window-stack order, carrying blockers accumulated from higher windows. Eligibility requires at least 6 DIP above the top (or a qualifying cross-display continuation), intersection with the display, owner-display membership, width ≥80 DIP, height ≥40 DIP, less than 90% of display-area coverage, and not a cover-only shell surface. Blockers intersecting the 40-DIP band above the ledge are attached for accumulation visibility; full-frame blockers also support face effects. Each layer keeps at most 16 GPU occluders, although visibility updates receive the full blocker list. This is rectangular occlusion, not pixel-perfect transparency analysis. (`windows/src/tracker.rs:304@HEAD`; `core/src/simulation.rs:1133@HEAD`.)

Hooks cover foreground, the movesize-start through minimize-end event range, object destroy through hide, location changes, cloaking/uncloaking; flags are OUTOFCONTEXT|SKIPOWNPROCESS. Callbacks mark dirty/moving state, filtering object/child and top-level ancestry so caret/control movements do not trigger full work. The refresh fallback is 0.5 seconds. Close/minimize therefore remove a surface on refresh, causing its layer to shed; moving/shaking is inferred by simulation from successive geometry, not an OS shake event. (`windows/src/tracker.rs:142@HEAD`, `:180`, `:637`; `core/src/simulation.rs:1143@HEAD`, `:2140`; [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook).)

VirtualDesktopManager distinguishes a cloaked window on another virtual desktop from a closed/hidden window: snow is made dormant for desktop changes and for windows that fill the work area, then restored. In contrast ordinary disappearing surfaces shed immediately. Abrupt snap/maximize motion uses a short nominal interval so the jump-speed detector leaves snow behind. (`windows/src/tracker.rs:160@HEAD`, `:412`, `:422`; `windows/src/screen.rs:376@HEAD`; `core/src/simulation.rs:1098@HEAD`, `:1143`.)

For snow, the taskbar is normally **not a tracked snow-carrying window**: `rcWork` supplies the ground edge. Behind Taskbar extends the bottom to `rcMonitor.bottom` and places snow beneath the bar. Auto-hide normally makes work area cover the display; a separate watcher hooks foreground/reorder and wakes the snow loop when Shell_TrayWnd/Shell_SecondaryTrayWnd overtakes an overlay. Explicit `taskbar_surface` creation at HEAD is for rain only. No ABM_GETSTATE query is used in these snow paths; auto-hide is handled via geometry/stacking. (`windows/src/screen.rs:58@HEAD`, `:97`, `:411`, `:598`, `:624`, `:730`.)

## 4. Snow model and formulas

Units are simulation DIPs with Y up. Airborne `Flake` records position, velocity, depth, size, alpha, softness, phase/sway, settling and mass; ejected `Grain`s and transient `Mote`s are separate. Ground is layer 0, windows are layers keyed by WindowId (HWND represented as isize). Each SnowLayer holds a 2-DIP-column **height field**, rounded underlying bed, visibility/support masks, position/velocity/offset, agitation and occluders; settled snow is not an ever-growing list of individual flakes. (`core/src/simulation.rs:20@HEAD`, `:22`, `:248`, `:285`, `:330`, `:1071`; `core/src/layer.rs:45@HEAD`.)

| Quantity | Observed snow formula/constants at HEAD |
|---|---|
| Intensity → density | Piecewise linear interpolation across `[0,150,380,800,1500]` flakes per million DIP² at intensity `[0,.25,.5,.75,1]`; snow-only target is integer-truncated `density * rate * width * height / 1,000,000` (`core/src/simulation.rs:139@HEAD`, `:1724`). |
| Spawn | Fill deficits to target; new flakes start at `height + U(0,height)`; X is `U(-30,width+30)` (`core/src/simulation.rs:1486@HEAD`, `:2691`). |
| Depth/fall | 2% foreground flakes; otherwise depth=`U(0,1)^1.6`. Foreground speed 75–100 DIP/s, ordinary `16+50*depth+U(0,10)` (`core/src/simulation.rs:2687@HEAD`). |
| Size/appearance | Foreground size 8–13, alpha .28, softness .95 and never settles; ordinary size `1.4+4.4*depth+U(0,1)`, alpha `.4+.5*depth`, softness `.75-.45*depth` (`core/src/simulation.rs:2694@HEAD`). |
| Sway | Rate U(.5,1.4); ordinary amplitude U(4,9)+10*depth. Horizontal offset velocity is `(cos(phase)+.3*cos(2.3*phase))*amplitude`; vertical velocity multiplied by `1+.12*sin(1.3*phase)`; phase wraps at 20π (`core/src/simulation.rs:39@HEAD`, `:2699`, `:2885`). |
| Breeze | `10*sin(.07*t)+6*sin(.19*t+1.7)+3*sin(.43*t+4.1)`; wind component depends on depth (`core/src/simulation.rs:2692@HEAD`, `:2800`). |
| Deposit/relaxation | Deposition scale 1.1; landing checks crossed layer heights, visibility and optional ground; deposited area uses size² scaling. Repose .8, rounding .15; repeated relaxation moves excess and spills at open edges (`core/src/simulation.rs:31@HEAD`, `:1293`, `:1668`; `core/src/layer.rs:335@HEAD`, `:419`). |
| Nominal depths | Ground depth 40, ledge depth 14; thaw reference floors 8 and 4 respectively (`core/src/simulation.rs:23@HEAD`). |
| Limits | Gravity 2500, grain drag .8, max grains 12,000, max motes 1,500; these are not a cap on all airborne flakes (`core/src/simulation.rs:36@HEAD`, `:63`, `:1724`). |

Motion attachment is physical lag, friction and inertia: support tracks use a 0.06-second smooth-damp; acceleration is change in smoothed velocity/dt. With stick=3500, grip=3, slip=2, vertical relative acceleration is `-2500-support_acceleration.y`, pressure is `max(2500+stick+acceleration.y,0)` while attached, horizontal drive is `-acceleration.x`, static hold threshold is `grip*pressure`, sliding friction is `slip*pressure`. Crossing a column width slides height-field mass off an edge; lift above 10 DIP releases the heap. Motion faster than 6000 DIP/s is a jump that sheds rather than transports; resize distinguishes fixed/moving edges and remaps columns. (`core/src/simulation.rs:41@HEAD`, `:60`, `:2066`, `:2140`, `:2219`.)

Shake detection needs repeated reversed accelerations: agitation decays with exp(-dt/.3); direction reversals compare consecutive swing peaks, normalized by gravity. Agitation >4 permits snow spray with rate `min(.06*(agitation-4),.8)`, randomly halves selected column heights and emits that mass with added upward/lateral velocity. Strong agitation also reduces repose to 35%, flattening piles. It is not a single displacement threshold or reliance on Windows Aero Shake. (`core/src/simulation.rs:2146@HEAD`, `:2224`, `:1693`.)

The cursor is sampled globally with GetCursorPos, converted to screen-local DIPs, offset (4,-8), and sweeps a radius-10 circle. Velocity uses dt≥1/240 and clamps to 3000 DIP/s; samples interpolate at ≤5-DIP spacing, while jumps >400 DIP carve only the endpoint. Slow displacement pushes snow to either side; spray fraction is smoothstep(60,420,speed). A buried cursor removes only swept volume and supports snow above; emitted mass becomes grains/motes. (`windows/src/screen.rs:566@HEAD`; `core/src/simulation.rs:34@HEAD`, `:1186`, `:2515`, `:2594`; [GetCursorPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorpos).)

Airborne flakes also respond to the cursor wake independently of the setting called Deep Interaction: wake activates above speed 20, caps speed at 500, reaches 80 DIP, and pulls velocity toward wake velocity by `min((1-distance/80)^2*4*dt,1)`. **Deep Interaction specifically adds the desktop selection rectangle as a synthetic ledge**, derived from primary-button/pointer movement, and is enabled only with window accumulation. (`core/src/simulation.rs:2787@HEAD`, `:2891`; `windows/src/tracker.rs:201@HEAD`, `:345`; `windows/src/snow.rs:336@HEAD`; `windows/src/app.rs:401@HEAD`.)

Melting uses snow-only `melt_pace=(falling/184)^.74` (1 when no falling density), scales dt, and removes `min(h,(.02+max(h-floor,0)/30)*scaled_dt)` from a column. Floors 8/4 slow excess loss but do not preserve a permanent minimum, since the constant loss remains. Disabling accumulation/ground causes melting toward zero. Clear Snow initiates a sweeping gust (sweep .6 s, duration 2.2 s, wind 1000, airborne lag .3 s), rather than simply deleting buffers; a calm option is passed into blow_away. (`core/src/simulation.rs:25@HEAD`, `:64`, `:1523`, `:1668`; `core/src/layer.rs:518@HEAD`; `windows/src/snow.rs:214@HEAD`.)

Falling Opacity is percentage/100 passed to `simulation.falling_opacity`; the field's contract applies to falling sky/window snow, while settled piles retain full appearance. Global DirectComposition opacity is a separate fullscreen-fade mechanism. (`windows/src/snow.rs:139@HEAD`, `:618`; `core/src/simulation.rs:430@HEAD`; `windows/src/render.rs:460@HEAD`.)

## 5. Rendering

Snow sprites are procedural quads using four-vertex instanced triangle strips; per-instance inputs carry position, velocity, size/alpha/softness and appearance attributes. The vertex shader uses vertex IDs, stretches along movement for streaking and adjusts small-pixel alpha. The snow pixel branch computes radial smooth coverage and lighting and returns premultiplied color. Snow does not require flake image textures. (`windows/src/render.rs:207@HEAD`, `:502`, `:596`; `windows/src/shaders.hlsl:759@HEAD`, `:782`, `:947`, `:990`; [DrawInstanced](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-drawinstanced).)

Piles are one quad per layer, sampling a float buffer of smoothed column data. `write_layers` packages origin/count/height offset and occluders; shader height interpolation creates the continuous top edge, discards covered regions and shades depth/slope with glints. This is a height-field shader, not a mesh with a vertex per snow grain and not a full-screen general SDF scene. Dynamic buffers are mapped WRITE_DISCARD; capacity is reserved/reused. (`core/src/simulation.rs:965@HEAD`; `core/src/layer.rs:108@HEAD`; `windows/src/render.rs:480@HEAD`, `:548`, `:648`; `windows/src/shaders.hlsl:1086@HEAD`, `:1095`, `:1103`.)

The render target is cleared transparent black; ordinary blending uses ONE and INV_SRC_ALPHA, ADD for both color and alpha, consistent with premultiplication. Present uses sync interval 1. HEAD contains additional non-snow field/glass/texture passes that need not be reproduced for snow. (`windows/src/render.rs:234@HEAD`, `:491`, `:613`, `:618`; [Present](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgiswapchain-present).)

## 6. Performance, power and pauses

Interactive target is monitor refresh clamped to 60–120. Calm is 30 FPS; Saver chooses 24 only if the interactive target is divisible by 24, otherwise 30. Lively is capped at 60; Interactive uses the full target on mains but ≤60 on battery/Saver. Max Performance overrides the selected rate with the interactive target, even on battery; it does not remove the hard 120 target clamp. Actual schedules are refresh-divisor quantized. Frame dt clamps to .05 seconds. Empty simulations check again after one second; unchanged piles skip frames except periodic glints. (`windows/src/screen.rs:264@HEAD`, `:308`, `:331`; `core/src/simulation.rs:824@HEAD`.)

GetSystemPowerStatus is queried in once-per-second chores; SystemStatusFlag==1 means Saver, otherwise ACLineStatus==0 means Battery, otherwise Full; failure defaults Full. Saver reduces simulation density to .75; ordinary battery reduces frame budget without reducing density. (`windows/src/snow.rs:275@HEAD`, `:283`, `:625`; [GetSystemPowerStatus](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getsystempowerstatus), [SYSTEM_POWER_STATUS](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-system_power_status).)

The controller registers WTS session notifications and GUID_CONSOLE_DISPLAY_STATE power notifications; session lock/disconnect and display-off state drive `Active(false)`, stopping simulation/drawing and parking the shell poller. Unlock/connect/display-on resume. Fullscreen detection combines window bounds with SHQueryUserNotificationState's BUSY/RUNNING_D3D_FULL_SCREEN/PRESENTATION_MODE states; a full-size nonzoomed window, or foreground zoomed window while shell is busy, covers a display. This is a heuristic, not an exact GPU occlusion query. (`windows/src/app.rs:217@HEAD`, `:250`, `:260`, `:337`; `windows/src/snow.rs:236@HEAD`; `windows/src/tracker.rs:393@HEAD`, `:693`; [WTSRegisterSessionNotification](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/nf-wtsapi32-wtsregistersessionnotification), [RegisterPowerSettingNotification](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerpowersettingnotification), [SHQueryUserNotificationState](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryusernotificationstate).)

Fullscreen cover fades out over .25 s, then SW_HIDE and no simulation frames on that display; hidden displays are revisited at 4 Hz. Uncover fades in over .35 s. Show over Full Screen bypasses cover, and after a .3-second stable state reshapes the ground to the display bottom while the fullscreen app hides the taskbar. GPU/frame failures rebuild the device and overlays. (`windows/src/screen.rs:35@HEAD`, `:440`; `windows/src/snow.rs:356@HEAD`, `:386`, `:408`.)

Upstream README reports about **6% of one processor core and 65 MB**, without a reproducible Windows hardware/display/intensity matrix at that statement. Treat as a product claim, not our benchmark or a guaranteed budget. The implementation logs snow-thread frame cost/sprite counts/window-listing cost twice a minute; these statistics are also not whole-process CPU or working set. (`README.md:33@HEAD`; `windows/src/snow.rs:639@HEAD`.)

Windows features enable D3D11/DXGI/DirectComposition/FXC, DWM/GDI, Direct2D/DirectWrite/WIC, COM, power, registry, remote desktop, performance/threading, accessibility/input/shell/window messaging; HEAD adds Globalization and Controls relative to MIT.
